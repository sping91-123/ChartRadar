# Chrome 선물 조건 알림 연결

## 원인과 수정

- 기존 브라우저 알림은 글로벌 로컬 프리셋 감시에 연결되어 있었다. 서버가 평가하는 BTC/ETH 선물 조건의 `push_alert_events`를 Chrome Notification으로 표시하는 연결은 없었다.
- 로그인한 웹 사용자의 새 선물 알림 기록만 60초 간격으로 확인한다. `rule_id=perpetual_scenario`로 조회 범위를 제한하고, 서버의 기존 감시 조건 및 Basic/Pro 권한은 그대로 사용한다. 시세를 재분석하거나 분석 사용량을 소비하지 않는다.
- Chrome Web Locks와 계정별 전달 기록으로 여러 탭의 요청·알림 중복을 줄인다. 이미 읽은 알림, 연결 전에 생성된 알림, 10분 넘은 알림, 잘못된 분석 링크는 표시하지 않는다.
- 알림 선택 시 당시 snapshot 및 monitor 문맥을 보존하고 읽음 처리한다. 로그아웃/계정 변경 이후 늦게 도착한 응답은 표시하지 않는다.
- 감시 화면과 코인 알림 설정에 브라우저 권한 및 수신 테스트 버튼을 추가했다. 테스트에는 실제 조건 발생이 아니라는 표시가 있으며 전환 이벤트를 생성하지 않는다.
- 저장된 감시는 분석 유효 시간이 지나도 바로 열 수 있다. 새 감시를 저장하는 조건은 그대로 유지했다.

## 지원 범위

사이트 탭을 열어 둔 Chrome의 알림이다. 서비스 워커/Web Push 구독은 추가하지 않았으며, 탭 종료 이후의 백그라운드 웹 푸시를 지원한다고 표현하지 않는다. 서버 감시는 최대 5분 간격이며 웹은 새 기록을 1분 간격으로 확인한다. OS/브라우저 알림 차단과 탭 절전 상태에 따라 표시가 지연될 수 있다. 전체 기록은 알림 기록 화면에서 확인할 수 있다.

## 검증

- TypeScript 전체 검사, production build, `git diff --check` 통과.
- `test-browser-perpetual-alerts`, 기존 `test-push-targets`, `test-perpetual-activation`, `test:perpetual-monitors`, `smoke:copy`, `smoke:billing` 통과.
- 외부 Chrome, 실제 Notification 생성자를 사용한 로컬 응답 fixture: 수신 테스트와 선물 조건 알림 모두 `show` 이벤트 확인. Notification 자체는 mock하지 않았다.
- 선물 조건 알림 한 번 표시, 클릭 콜백의 당시 분석 복귀와 monitor 문맥 유지, 다른 탭의 중복 0건, 로그아웃 이후 지연 응답의 노출 0건 확인.
- 390×844에서 가로 넘침 없음. 만료된 분석에서도 저장된 감시 접근 확인.
- Windows 알림창 직접 클릭은 미검증이다. Computer Use가 현재 Chrome 주소를 확실히 판별하지 못해 중단됐다. 프로그램으로 실행한 클릭 콜백 검증을 OS 직접 클릭 성공으로 표현하지 않는다.
- 증거: `output/playwright/browser-notify-2026-09-07/` (로컬 fixture, 캡처; git 제외).
