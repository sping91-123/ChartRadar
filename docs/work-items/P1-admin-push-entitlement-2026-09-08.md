# 관리자 계정에서 일반 Pro 푸시가 발송되지 않는 문제

## 운영 조사

- 사용자 제보: 전날 평소 사용하는 휴대폰에 알림을 설정했지만 알림이 오지 않았다. 이전 USB 테스트폰과는 다른 기기다.
- 2026-09-08 09:36 KST 기준 운영 크론은 실행 중이었다. 전날 21:00 KST 이후 조회된 `/api/push-cron` 요청에서 HTTP 200 152건을 확인했다.
- 해당 계정의 BTC 감시는 전날 13:50 KST 저장됐으며 09:35 KST에도 검사했다. 저장 이후 조회된 BTC 분석 918건은 모두 데이터 정상(`ready`)·방향 충돌(`risk`) 상태였다. 저장한 방향 정렬 조건의 실제 충족/발송 이벤트는 없었다. 이는 휴대폰 수신 실패와 구분한다.
- 일반 알림의 권한 판정은 구독 행만 사용했다. 관리자 계정은 별도 유료 구독 행 없이 앱에서 Pro 기능을 사용할 수 있지만, 일반 푸시 스캐너에는 신뢰된 관리자 역할이 전달되지 않아 Basic으로 판정됐다.
- 해당 계정의 최근 48시간 이벤트는 이전 USB 테스트폰 검증용 알림뿐이었다. 이 기록은 평소 쓰는 휴대폰의 수신 증거가 아니다.
- 평소 휴대폰에 대한 최신 기기 등록 및 수신 여부는 별도 확인이 필요하다. 오래된 등록 시각만으로 연결 실패라고 단정하지 않는다.

## 변경 범위

- 일반 푸시의 계정 권한을 서버 Auth에서 읽은 `app_metadata.role`과 기존 구독 원장으로 판정한다.
- 계정 삭제 대기/처리/실패 상태, 삭제된 계정, 다른 사용자 ID의 응답은 발송 대상에서 제외한다. Auth 또는 삭제 상태 조회 실패도 기존 사용자별 오류 처리로 발송을 중단한다.
- 사용자 편집 가능한 metadata는 권한 근거로 사용하지 않는다. Basic/시장별 구독/만료/회수 경계를 유지한다.
- 시장 조건, 점수 기준, 확정봉 판단, 감시 만료, 알림 선택과 중복/빈도 제한은 변경하지 않는다. 인위적 조건 충족이나 전체 사용자 테스트 푸시는 수행하지 않는다.
- 각 계정 검사에 Auth 및 삭제 상태 읽기 요청이 추가된다. 각 요청은 5초 제한을 두며 운영 크론 실행 시간을 확인한다.

## 검증

- `npm.cmd run test:push-entitlements`: 실제 일반 스캐너를 모의 데이터로 실행하여 관리자 발송, Basic 차단, 사용자 metadata 위조 차단, 유료 코인 권한, 주식 접근 차단, 만료/회수/삭제/조회 실패를 검증했다. 실제 FCM은 호출하지 않았다.
- `npm.cmd run smoke:billing`: 통과.
- `npm.cmd run build`: production build 및 타입 검사 통과.
- `npm.cmd run test:push-targets`, 기존 entitlement matrix: 통과.
- `git diff --check`: 통과. 운영 배포 확인 진행 중.
