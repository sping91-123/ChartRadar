# 푸시 후보를 품질 검사 전에 제외하는 오류

## 문제

코인 스캐너는 모드마다 코인별 최고점 후보와 상위 개수만 남겼다. 일반 이벤트 생성에서도 상위 순위와 시장별 발송 개수 제한을 먼저 적용한 뒤, 실제 발송 단계에서 시간대·점수·근거 품질을 확인했다.

이 순서에서는 높은 점수의 제외 대상 5분봉이 같은 코인의 유효한 15분봉을 가리고, 근거가 부족한 알트가 다른 유효한 알트의 자리를 차지할 수 있었다. 전체 상위 순위가 알트로 채워지면 별도 발송 한도가 있는 BTC·ETH도 제외됐다.

## 수정

- 이미 계산한 시간대별 스캔 결과를 후보 선별까지 유지한다. 거래소 요청을 추가하지 않는다.
- 알림 품질을 먼저 검사한 후 코인별 최고 후보와 알트/메이저 발송 한도를 적용한다.
- 기존 품질 거절 진단을 위한 샘플은 별도로 유지하며 발송 한도에는 포함하지 않는다.
- 점수 계산, 품질 기준, 확정봉 판단, 구독 권한, 중복/빈도 제한은 변경하지 않는다.

## 검증

- `npm.cmd run test:push-candidates`: 수정 전 시간대 보존·같은 코인 대체 시간대·알트 슬롯·메이저 보존 검사가 실패함을 재현했다. 수정 후 모두 통과했다.
- 품질 미달/5분봉 제외, 동일 코인 중복 방지, 기존 발송 개수 제한, 빈 입력을 함께 검증한다.
- `npm.cmd run test:push-entitlements`: 통과.
- 실제 휴대폰 수신과 과거 누락 건수는 이 모의 검사만으로 확정하지 않는다.

- `npm.cmd run test:push-targets`, `npm.cmd run smoke:billing`, `npm.cmd run build`, `git diff --check`: 통과.
- 커밋·푸시·운영 배포를 완료했으며 같은 코드 커밋의 운영 도메인 연결을 확인했다.
- 운영 자동 스캔에서 시간대별 후보가 선별 단계까지 유지되는 것을 확인했다. 해당 스캔의 조회·스캐너 오류는 없었다.
- 외부 Chrome의 모바일 화면에서 홈·알림 설정의 진입, 가로 넘침, 콘솔 오류를 검사했다. 상태 API, Basic 권한, 보호 API의 비인증 차단도 통과했다.
- 기존 일부 푸시 발송 실패는 남아 있다. 이번 후보 선별 수정이나 모의 검사만으로 전체 기기의 정상 수신을 확정하지 않는다.
