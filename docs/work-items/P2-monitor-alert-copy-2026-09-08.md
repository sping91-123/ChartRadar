# 조건 감시의 대상과 알림 시점 설명

- 요청: 처음 사용하는 사람이 무엇을 감시하고 언제 무엇을 알려주는지 이해할 수 있게 문구와 배치를 다듬는다.
- 상태: 로컬 구현 및 검증 완료. 대표의 ‘다 다듬고 나면 알아서 커푸배까지 진행’ 지시에 따라 커밋·푸시·운영 배포를 진행한다.

## 확인한 실제 기준

- 판단 변경 감시는 명시적 targetState가 없으면 저장 상태와 달라진 상승/하락 우세 상태만 알린다. 신호 엇갈림과 방향 대기 사이의 이동은 알리지 않는다. ‘판단이 바뀌면’이라는 설명만으로는 범위가 너무 넓었다.
- 가격 조건은 해당 시간대 확정봉 종가가 기준 이상/이하일 때 충족한다. 일시적인 현재가 접촉은 알리지 않는다.
- 청산 압력은 저장한 기준과의 변화 또는 명시한 목표 상태를 확인한다.
- 감시는 최대 5분 간격으로 확인하며 조건 충족 후 1회 기록하고 종료한다. 앱 푸시는 연결 상태가 필요하다.

## 수정

- Home의 ‘이 조건 감시 설정’을 실제 조건별 버튼 문구로 변경했다. 방향 조건은 ‘방향이 뚜렷해지면 알림 설정’, 가격 조건은 시간봉·가격·마감 기준을 표시한다. 다음 화면에서 확인 후 저장하는 단계도 설명한다.
- 상세 화면은 버튼 바로 위에 구체적인 알림 발생 조건, 확인 간격, KST 종료 시각을 둔다. 저장된 조건이 있으면 기존 감시의 종료 시각을 사용한다.
- 가격 설명을 실제 비교 연산과 일치하는 ‘이상으로/이하로 마감’으로 정리했다. 숫자를 포함한 긴 버튼은 모바일에서 줄바꿈되며 ‘알림 받기’를 한 덩어리로 유지한다.
- 저장 성공/실패 안내를 버튼 바로 아래로 옮겼다. 성공하면 무엇을 기다리는지 다시 명시한다.
- 저장 목록과 Pro 추가 조건도 동일한 알림 기준을 사용한다. 알림함 기록, 푸시 연결, 조건 충족 후 종료를 구분한다.
- 과거 분석에서는 새 감시 안내를 노출하지 않고 기존 가격 고정과 현재 분석 이동을 유지한다.
- 평가 엔진, 조건 ID와 저장 요청, 봉 마감 기준, 감시 한도, 권한 및 발송 로직은 변경하지 않았다.

## 검증

- production build 및 TypeScript 검사 통과. 로컬 Home 정적 생성도 운영과 동일한 기능 on 상태로 확인했다. 환경 파일이나 운영 설정은 수정하지 않았다.
- `npm.cmd run test:perpetual-snapshot`, `npm.cmd run smoke:copy`, `npm.cmd run smoke:billing`, 기존 push target 회귀 검사 통과.
- 외부 Chrome 모의 API/계정으로 Home → 상세 → Basic 저장 → 저장 목록까지 확인했다. 실제 DB 저장이나 푸시 전송은 하지 않았다.
- 360/390/508px에서 방향, 반대 방향, 가격 이상/이하, 청산 압력 버튼을 확인했다. 가로 넘침이 없고 새 저장 버튼은 최소 44px 높이를 유지한다.
- 데이터 지연 시 저장 비활성, 과거 가격 79,066 고정과 새 감시 차단을 확인했다. 최종 브라우저 page error 0건.
- 검수 중 ‘이하으로’ 조사를 수정하고 재빌드·재검증했다.
