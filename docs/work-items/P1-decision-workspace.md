# 내 조건과 판단 기록 이어보기

## 문제와 변경

분석을 저장한 뒤 어디서 이어 볼지 불분명했고, 감시 상태와 복기가 떨어져 있었다. 기존 복기 작성은 새 수기 기록을 만들기 때문에 당시 분석과 이후 판단을 한 기록에서 확인하기 어려웠다.

- 홈의 주요 일정을 분석보다 위에 유지하고, 그 아래에 내 조건·판단 기록으로 이어지는 진입점을 둔다.
- `/crypto/tracking`에서 기다리는 조건, 마지막 검사 상태, 종료 시각, 종료된 조건과 저장한 판단을 함께 확인한다. 저장 당시 분석과 현재 분석을 구분한다.
- 분석 저장 후 반환된 기록으로 바로 연결한다. 조건 관리 연결은 감시 목록을 펼친다.
- 기준 유지·기준 수정·관망 유지·자료 부족 중 하나와 다음 확인 기준을 원래 판단 기록에 저장한다. 원본 분석과 기록 식별자를 보존한다.
- 기존 수기 기록과 로컬 보관 기록의 작성 흐름은 유지한다.

## 데이터와 집계 기준

기존 `journals.decision_context`의 JSONB에 사용자 확인 기록만 추가한다. 스키마 변경은 없다. 서버가 확인한 사용자 식별자로 모든 읽기·수정을 제한한다. Basic 사용자는 자신의 기존 기록을 확인할 수 있으며, 조건 수와 Pro 분석 공개 범위는 기존 정책을 따른다.

최근 정상 검사는 만료되지 않은 활성 조건 중 최근 7분 내 정상 자료를 검사한 조건이다. 판단 재확인 수는 최근 저장한 최대 20개 중 사용자가 실제로 확인 기록을 남긴 개수다. 화면의 수치는 절약 시간, 매매 수익, 적중률 또는 구독 가치가 입증됐다는 의미가 아니다.

## 검증

- `npm.cmd run test:decision-workspace`: 계정별 접근, 원본 보존, 입력 제한, 장애 응답, 집계 제외 조건.
- `npm.cmd run test:perpetual-monitors`, `node .verify-dist/scripts/test-perpetual-activation.js`: 기존 조건 추적 동작.
- `npm.cmd run test:auth-boundaries`, `npm.cmd run test:product-events`, `npm.cmd run smoke:billing`: 인증·기록·상품 정책 회귀.
- `npm.cmd run build`, `git diff --check`.
- 모바일 Chrome: 홈 일정 순서, 저장 후 정확한 기록 연결, 감시 관리 펼침, 저장 실패 후 입력 유지·재시도·다시 불러오기, 계정 전환, 로그인 복귀 주소, 가로 넘침과 콘솔 확인.

브라우저의 로그인·개인 기록 저장 시나리오는 격리된 테스트 응답을 사용한다. 실제 데이터베이스의 기존 JSONB 컬럼과 소유자 RLS 정책은 읽기 전용으로 확인한다. 실사용자의 장기간 활용, 유료 전환, 실제 휴대폰 푸시 수신을 이 검증의 결과로 주장하지 않는다.
